# Добавление фото товаров

Это руководство показывает, как вывести реальные фото товаров на сайт, не трогая код.
Файлу достаточно оказаться в нужной папке с нужным именем — сайт подключит его
автоматически при следующей сборке.

Пока фото нет, товар показывает нейтральный плейсхолдер **«Фото уточняется у
менеджера»**. Это нормально и безопасно: сайт никогда не покажет изображение, которое
не соответствует товару.

## 1. Подготовьте фото

Каждое фото товара должно соответствовать требованиям:

- **Формат:** WebP. AVIF допустим, но не обязателен.
- **Ориентация:** портрет **4:5**, ровно **1600 × 2000 px**.
- **Композиция:** устройство по центру с ровными отступами по всем сторонам.
- **Фон:** прозрачный **или** единое **#F7F7F9** (светло-серый) — без рамок и
  подложки вокруг устройства.
- **Без текста, без водяных знаков** на кадре.
- **Размер файла:** ≤ 300 KB.

Два способа подготовить фото:

- **Бесплатный онлайн-инструмент:** [Squoosh](https://squoosh.app) — откройте фото,
  задайте размер 1600 × 2000 px, выберите WebP и сохраните.
- **Встроенный скрипт (локально, без сети):**

  ```bash
  npm run images:prepare -- <входящий-файл> <slug>
  ```

  Пример — владелец скинул фото iPhone 17 Air:

  ```bash
  npm run images:prepare -- ./photos/iphone-17-air.jpg iphone-17-air-space-black-front
  ```

  Скрипт resize-ет исходник в 1600 × 2000 (4:5, по центру, на фон #F7F7F9 — или
  сохраняет прозрачность, если у исходника есть альфа-канал), конвертирует в WebP с
  качеством ~82 и записывает в `public/images/products/<slug>.webp`. Локальная
  пересклейка без ретуши и без сети.

## 2. Имена файлов

Правила:

- только строчные латинские буквы и цифры,
- слова разделяются дефисами (`-`), без пробелов и подчёркиваний,
- точный slug из таблицы ниже.

Товары, которые сейчас ждут фото:

| Товар | Точное имя файла |
| :--- | :--- |
| iPhone 17 Air (Space Black) | `iphone-17-air-space-black-front.webp` |
| iPhone 16 Pro | `iphone-16-pro-front.webp` |
| MacBook Neo 13 A16 | `macbook-neo-13-a16-front.webp` |

Шаблон для любого товара: **`{model-slug}-{color-slug}-front.webp`**

- `model-slug` — slug модели товара, например `iphone-17-air`, `macbook-neo-13-a16`.
- `color-slug` — цвет в строчных буквах с дефисами, например `space-black`. Если у
  товара нет цветовых вариаций — без части с цветом (например
  `iphone-16-pro-front.webp`).
- `front` — передний вид. Дополнительные ракурсы используют саффиксы:
  `-back`, `-side`, `-detail` (например `iphone-17-air-space-black-back.webp`).

## 3. Куда класть файл

Сложите файл в:

```
public/images/products/
```

Например: `public/images/products/iphone-17-air-space-black-front.webp`.

## 4. Проверка, что файл обнаружен

Запустите:

```bash
npm run images:check
```

Скрипт выведет все ожидаемые фото товаров и то, найдены ли они. У добавленного файла
должна быть метка `✓`. Такая же проверка проходит автоматически в конце `npm run build`
в качестве предупреждения.

## 5. Товар с несколькими цветами

Если товар продаётся в нескольких цветах, на каждый цвет нужно своё фото со своим
color-slug в имени файла:

- `iphone-17-air-space-black-front.webp`
- `iphone-17-air-midnight-front.webp`
- ...

Магазин показывает фото, соответствующее выбранному цвету. Если фото для какого-то
цвета пока нет — для этого цвета остаётся плейсхолдер, остальные цвета работают.

## 6. Сборка и развёртывание

```bash
npm run build
```

Затем разверните сайт по инструкции в `README.md` (обычные шаги деплоя), либо пусть
хостинг сделает автосборку, если она настроена. Фото появится после сборки, в которую
вошёл файл.

## 7. Как проверить

1. Откройте **каталог** (`/catalog/`) и **страницу товара**
   (`/catalog/<категория>/<модель>/`).
2. Проверьте на **375 px** (телефон) и **1440 px** (десктоп).
3. Плейсхолдер должен пропасть — показано реальное фото.
4. Посмотрите на фото: оно не должно быть растянутым, сжатым или искривлённым. Если
   так — у файла, скорее всего, неправильный формат (см. ниже).

## 8. Решение проблем

- **Плейсхолдер всё ещё показывается.** Проверьте по порядку:
  1. имя файла в точности как требуется (строчные буквы, дефисы, правильный slug);
  2. файл лежит в `public/images/products/`, а не в другом месте;
  3. вы сделали сборку после добавления файла (`npm run build`);
  4. кэш браузера — сделайте принудительный обновление страницы (Ctrl/Cmd + Shift + R).
- **Изображение размытое.** Исходник слишком мал — файл должен быть 1600 × 2000 px
  (или больше до ресайза). Пересохраните в полном размере.
- **Изображение обрезано или растянуто.** Неверный формат — фото должно быть 4:5
  (1600 × 2000). Пересохраните с правильным форматом; сайт показывает файл как есть.
- **Страница стала медленной.** Файл слишком большой — укладывайтесь в 300 KB.
  Пересохраните с более низким качеством WebP.

## 9. Дополнительные ракурсы (галерея), замена и удаление

- **Больше ракурсов:** добавьте файлы со саффиксами `-back`, `-side`, `-detail`
  (например `iphone-17-air-space-black-back.webp`). Галерея подхватит их автоматически.
- **Замена фото:** положите новый файл с тем же именем поверх старого и сделайте
  сборку. Код трогать не нужно.
- **Удаление фото:** удалите файл из `public/images/products/` и сделайте сборку —
  плейсхолдер вернётся автоматически.

Вопросы по конкретному товару? Посмотрите точное ожидаемое имя файла в
`src/data/images.json` (раздел `products`) или запустите `npm run images:check`.
