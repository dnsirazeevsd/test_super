# Нужные фото магазина (плейсхолдеры → реальные файлы)

Секция «Магазин» на `/contacts/` сейчас показывает CSS-плейсхолдеры. Положите реальные
файлы в `public/images/store/` — они заменят плейсхолдеры автоматически при следующей
сборке (реестр: `src/data/images.json`).

| Файл | Размер | Слот | Что снимать |
| :--- | :--- | :--- | :--- |
| `store-1.webp` | 2400×1350 (16:9) | широкий, первый | Вход/витрину магазина так, как её видит покупатель при подходе |
| `store-2.webp` | 1600×1200 (4:3) | ряд, 1-й | Торговый зал |
| `store-3.webp` | 1600×1200 (4:3) | ряд, 2-й | Витрины с устройствами |
| `store-4.webp` | 1600×1200 (4:3) | ряд, 3-й | Зона обслуживания/консультаций или вход в магазин из коридора ТРЦ |

**Гайд по съёмке:**
- Горизонтальная (ландшафтная) ориентация для всех кадров.
- Дневной свет либо равномерный свет магазина; без пересветов витрин.
- Без лиц посетителей и сотрудников; без клиентских данных на экранах устройств.
- Без посторонних людей крупным планом — «живая», но нейтральная обстановка.

**Подписи/alt (опционально):** заполните `storePhotos[i].alt` и `storePhotos[i].caption`
в `src/data/site.json`. Подпись показывается только если заполнена; alt по умолчанию —
«Магазин SUPER STORE в ТРЦ «РИО», фото N». Не описывайте этаж и планировку ТРЦ в текстах UI.

## Фото товаров (ждём фото от владельца)

Три позиции пока показывают плейсхолдер «Фото уточняется у менеджера» в каталоге и на
странице товара. Владелец добавит фото вручную — положите файл в `public/images/products/`
с **точным именем** из таблицы, и он подключится автоматически при следующей сборке
(реестр ожидаемых файлов: `src/data/images.json` → `products`; проверка — `npm run images:check`).
Пока файла нет, плейсхолдер остаётся — изображение никогда не будет показывать несоответствующий товар.

| Продукт | Точное имя файла | Размер | Статус |
| :--- | :--- | :--- | :--- |
| iPhone 17 Air (Space Black) | `iphone-17-air-space-black-front.webp` | 1600×2000 (4:5) | ждём фото от владельца |
| iPhone 16 Pro | `iphone-16-pro-front.webp` | 1600×2000 (4:5) | ждём фото от владельца |
| MacBook Neo 13 A16 | `macbook-neo-13-a16-front.webp` | 1600×2000 (4:5) | ждём фото от владельца |

**Спецификация каждого файла:**
- WebP (AVIF допустим, но не обязателен), портрет 4:5, ровно **1600×2000 px**.
- Устройство по центру с ровными margins (равномерные отступы по всем сторонам).
- Прозрачный фон или единое #F7F7F9; без текста, без водяных знаков; размер файла ≤ 300 KB.

**Гайд по съёмке:**
- Передний (front) вид устройства, устройство строго по центру.
- Ровный светлый фон, без отражений и бликов, без рук в кадре.
- Без текста, надписей и водяных знаков на кадре.

**Подсказка:** если готовый файл уже есть, можно сразу отдать его (WebP) — положить по
пути из таблицы. Если есть исходник другого размера/формата, подготовить локально можно:
`npm run images:prepare -- <входящий-файл> <slug>` (resize в 1600×2000, 4:5, фон #F7F7F9,
WebP q82 — без ретуши и без сети). Подробности — `docs/ADDING-PRODUCT-PHOTOS.md`.

## Хиро-изображение главной (бесшовный белый фон)

Hero на `/` показывает рендер iPhone 18 Pro напрямую на чистой белой поверхности страницы
(без серой подложки). Требование к замене изображения:

- **Прозрачный катчаут (PNG/WebP с альфой)** устройства + его мягкая студийная тень —
  идеальный вариант: устройство встанет на белый фон бесшовно при любом фоне секции.
- Допустимый вариант — рендер на **чистом белом (#FFFFFF)** фоне без рамки/подложки
  (текущий `iphones/iphone-18-pro-glacier` уже такой и тает в фоне страницы).
- Не использовать изображения с серым/цветным фоном-плашкой.
- Файл-катчаут кладите в `assets/source/iphones/` и запустите `npm run optimize-images`,
  либо отдайте готовый WebP — подключим напрямую.
